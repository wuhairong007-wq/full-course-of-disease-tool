# 检索缺口草稿

## 何时使用

仅限用户明确要求“待核实基础资料草稿”的阶段 1，或完成自主检索后确实无法形成
任何合法完整模拟情境时使用。普通 `模式：模拟` 请求默认优先建立内部
`simulation-only` 参数目录并生成非空患者明细，不得因为研究缺口自动降级为空字段草稿。
先自主检索精确产品及剂型，记录实际阅读的说明书、监管资料、适用指南及原始研究。
可以检索病例报道，但不能仅因“有案例”就认定其用法适用于整批患者，更不能借用
复方或相似产品参数。

只有在上述模拟情境路径确实不可行，或用户明确选择本草稿时，才转为本草稿，不再要求
操作者提供材料或重复确认。
检索失败须如实记录，不能宣称完成查证；没有实际查阅来源时不能伪造审计记录。
真实模式、完整处方输出及后续阶段的安全与证据要求不变。

## 输出范围

- 使用原 16 列模板、一个工作表和一个表对象，保留所有患者及源顺序。
- A:K 继续保留源值，仅患者标签 `无` 按既有规则显示为 `正常`。
- 本草稿是整批基础资料导出，不是部分处方拼接。L:O 全部留空，不生成用药、
  处方、手术或耗材结论，包括 `关联厂家用药` 场景。产品关联不等于适用性通过。
- P 仅使用该行源 `疾病` 原文，不追加治疗、术后阶段或产品名。
- 文件正文不添加“模拟”“虚构”、免责声明、缺失说明、审核状态或额外列/表。
  不删除源字段中本来存在的文字。
- 文件名必须同时含 `模拟`（兼容 `虚构测试`）和 `待核实`，例如
  `<source-stem>_患者全病程数据_模拟_待核实.xlsx`；不得覆盖源文件或模板。
- 草稿不能作为已审核处方输入阶段 2～6，不得用留空字段凑足药品数或丰富性目标。
  普通 `模式：模拟` 的完整患者明细不得使用本草稿来规避非空字段要求。
  不宣称患者明细的完整处方已生成或临床校验已通过。

## 内部检索记录

在临时目录写入 `draft-review.json`，字段如下：

- `kind` 固定为 `fictional-draft-review/v1`。
- `sourceSHA256` 是当前源 Excel 字节的 SHA256，不使用历史输入的摘要。
- `searchedOn` 为实际检索日期，格式 `YYYY-MM-DD`。
- `queries` 为非空实际检索词数组。
- `sources` 为非空实际查阅来源数组，每项包含 `title`、HTTP/HTTPS `url`、
  `finding`。写明已确认内容、限制及未解决的问题，不把搜索摘要冒充原文查阅。
- `unresolved` 按源顺序覆盖全部患者，每项含 `userid`、非空 `parameters`
  数组及 `reason`。部分患者尚未完成审核时据实记录，不能假称其产品参数未知。

内部记录不是新的最终交付物，不写入患者工作簿。导出器只验证审计结构、源绑定
和模板，不证明文献真实性或患者适用性。

## 导出与验证

复用原导出器，新增模式只接受检索记录，不接受处方 `records` 或最少种数：

```bash
<bundled-node> scripts/build_workbook.mjs \
  --mode fictional-draft \
  --input <source.xlsx> \
  --review <temp>/draft-review.json \
  --template assets/patient-full-course-template.xlsx \
  --output <source-stem>_患者全病程数据_模拟_待核实.xlsx \
  --preview <temp>/draft-preview.png
```

导出结果应为 `status=draft`、`clinicalValidation=not-completed`，不能写成
`passed`。重新打开确认 16 列、全部 userid 及源顺序、A:K 源值、L:O 留空、
P 与源疾病一致、一个工作表及表对象，并检查预览。对话中说明草稿人数、未完成
的审核及留空范围，不要求操作者提供材料。

运行 `scripts/test_research_gap_draft.mjs`，验证草稿输出、源文件保护、缺失检索
记录和错误摘要拒绝、文件名标识，以及草稿不能冒充真实或完整模拟处方。
