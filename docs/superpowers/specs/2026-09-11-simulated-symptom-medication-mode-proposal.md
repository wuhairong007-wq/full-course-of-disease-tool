# 模拟症状与用药组合模式：未采用提案

本提案未实施。用户最终确认采用 [基于真实依据充分评估联合用药](2026-09-11-source-supported-medication-design.md)，不进行随机症状补全。以下仅保留原提案记录。

## 请求及待确认边界

请求：源表没有疼痛程度、炎症表现等信息时，随机分配这些信息，让生成的联合用药达到三种以上。

待确认：是否仅用于演示或测试，且允许输出明确标注“模拟病情、模拟用药方案，不用于实际诊疗”。未确认前不修改生成行为。

## 已核查的现状

- 已安装技能和仓库版本均为 1.1.14。
- 现有骨关节炎脚本根据 userid 与疾病计算稳定分层，分别生成一、二、三药组合。
- 当前模拟分层仅为内部数据，没有在最终患者工作簿中标明；普通阶段仍允许一至五种药。
- 分层不能证明真实患者有疼痛或炎症，也不能用来推断肝肾功能、合并症或过敏安全性。

## 建议行为

1. 仅在明确的演示或测试模式启用模拟补全。保留普通患者生成入口。
2. 只补全疾病允许的症状维度。保留真实年龄、性别、疾病和过敏史；不覆盖已有症状，不生成虚构检验结果或器官功能。
3. 支持显式随机种子。同一输入与种子可复现；改变种子仅改变模拟场景，不代表患者病情改变。
4. 把模拟字段及其标识写入可见输出，文件名称和模拟处方字段均标明模拟性质。不能只在内部 JSON 或对话中说明。
5. 三至五药仅作为模拟场景覆盖目标。药物必须分别具有适应证，不能通过虚构更多合并症、叠加等效药或加入无关药来补足数量。不满足时报告具体原因，不悄悄补药。
6. 模拟结果不得直接进入真实患者用药提醒、健康管理或统计报告流程。
7. 本次不自动重新生成此前的 1498 人工作簿。功能完成后更新版本号，并验证实际安装文件与仓库一致。

## 验收重点

- 模拟内容在最终文件可见；不能伪装为已观察到的患者事实。
- 固定种子可复现；真实字段及已有症状不变。
- 过敏或禁忌可以让模拟组合少于三药或停止，不被数量目标覆盖。
- 普通生成不受模拟入口影响；后续真实服务入口拒绝模拟处方。
- 没有“由临床医生/医师……”等被禁止的外部人员介入文案。

## 范围待定

现有专用脚本只覆盖骨关节炎。扩展到其他疾病需各自定义允许模拟的维度和药物适应证，不能使用一套随机症状通用于所有疾病。
