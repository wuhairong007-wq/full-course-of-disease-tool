# 基于真实依据充分评估联合用药

用户已确认：依据已有疾病和真实症状充分评估联合用药，有明确适应证时生成 3～5 种；依据不足时保留较少药物，不虚构病情或强行补药。

## 行为

- 阶段一读取可选症状字段，按原列名保留非空值为 symptomEvidence。数值 0、否定表现必须保留；缺少或空白字段不补值。原必需列、患者顺序和最终六键 records 契约不变。
- 逐人评估产品、病因/一线治疗、维持治疗、围手术期治疗、真实症状支持五类治疗角色。将候选药及其适应证、排除原因写入临时 medication-review.json，作为生成复核依据，不写入交付表。
- 三至五药是充分评估后可成立的结果，不是最低数量。已有依据支持一至两药时保留；每种药必须独立适用，不能重复叠加等效药。
- 普通患者明细流程禁止用 userid 哈希、随机数或臆测分配疼痛和炎症以制造适应证。移除该入口对旧模拟分层脚本的调用指引。
- 临床安全检查、药品规格、处方一一对应和过敏史约束继续生效。症状文本与诊断冲突时报告，不以随机信息修复。
- 更新到 1.1.15，验证后同步本机安装副本。此前患者输出文件不在本次变更范围。

## 验证

使用真实 XLSX→提取 CLI→JSON 集成测试，覆盖有症状、全空症状、没有可选列、零分和否定表现、userid 顺序以及过敏史保留。运行既有临床用药、规格、等效候选、生成内容和阶段一工作簿测试及完整性校验。
