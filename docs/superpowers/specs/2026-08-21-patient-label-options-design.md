# 患者标签选项扩展设计

## 目标

将患者明细中的`患者标签`合法值从`轻度 / 中度 / 高度`扩展为`无 / 轻度 / 中度 / 高度`，同时保持跟踪提醒的既有计算和人工干预规则，并扩大不良反应清单的入选范围。

## 跟踪提醒和用药清单

- 输入校验接受`无 / 轻度 / 中度 / 高度`。
- 体温、血压与心率、用药提醒、患者响应率及用药清单生成规则不变。
- `是否触发人工干预`继续按既有逻辑生成：`中度 / 高度`为`是`，`无 / 轻度`为`否`。
- `患者标签=无`的患者仍保留在跟踪提醒和用药清单中，不进行筛除。

## 不良反应清单

- 输入校验接受`无 / 轻度 / 中度 / 高度`。
- 排除`患者标签=无`的患者。
- 按源表顺序从`轻度 / 中度 / 高度`患者中选取前`N`位，不重复患者。
- `不良反应严重程度分级`原样复制患者标签。
- `是否触发人工干预`为：`高度`生成`是`，`轻度 / 中度`生成`否`。
- 临床叙述按严重程度保持相称；现有“高度患者必须体现紧急评估或专科干预”的校验继续保留。

## 兼容性

- 患者明细和健康管理方案阶段只保留患者标签字段，不使用标签决定用药或健康方案内容，因此不改变其生成逻辑。
- 固定17列表头、userid覆盖、时间边界、药物白名单和工作簿模板规则保持不变。
- 当可入选的`轻度 / 中度 / 高度`患者少于请求数量时，停止并报告实际可入选人数。

## 测试

- 跟踪阶段测试`患者标签=无`可通过输入校验，且人工干预为`否`。
- 不良反应阶段测试`无`被排除、`轻度`被纳入，输出顺序与源表一致。
- 测试严重程度原样复制，以及`轻度 / 中度 / 高度`分别映射为`否 / 否 / 是`。
- 运行技能结构校验和全部现有回归测试，确认其他阶段不受影响。
