# 模拟患者明细的药品数量与处方丰富性

用户授权阶段1根据相容的AI病情情境增加联合用药，生成内容不出现模拟说明，文件名标记模拟；恢复按记录数扩展实质处方的要求。

授权语句（例如“可以AI模拟病情增加药品种数”）直接选择 fictional-test，沿用同一任务授权。没有模拟授权的独立任务仍为 real。模拟模式省略最少种数时默认为3，支持显式1～5；真实模式保持1。根据相容情境核对3～5种不同治疗作用的药物；不能固定套用三药库来代替方案研究。保留患者源字段、过敏和公司排除规则。

沿用既有 ceil(sqrt(N)) 全批实质处方目标，取消方案库容量封顶。先按最终药品数、年龄、过敏、源证据及公司规则过滤方案，再以患者—实质处方匹配确认可达目标；不足时报出目标、可用数、缺口，要求检索指南与说明书扩展相容情境库，再重新生成。导出复核目标，不能悄悄降低。药品顺序、警示措辞与标点变化不增加实质种数。

最终文件名接受“模拟”或兼容既有“虚构测试”，生成单元格不含情境标识。维持17列、逐人药品与处方对应。交付说明模式并报告药品数分布、处方目标及实际去重数。无本次患者源表，因此本改动仅更新生成规则与程序，不编造医学方案库或声称已生成患者文件。

验证：省略最低种数、显式下限、公司排除、1498条/24种库的不足报错、合成扩容库达到39种、受限人群的可达性、语义重复、稳定分配、源字段保留及实际Excel导出。同步仓库和已安装技能，版本1.2.9。
