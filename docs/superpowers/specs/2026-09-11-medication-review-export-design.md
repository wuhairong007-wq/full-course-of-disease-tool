# 联合用药评估与导出校验

用户确认的目标是充分评估有依据的治疗和等效候选，允许合理单药或双药；不虚构病情，不强制最低三药。

1. 以疾病、分型、部位、治疗阶段和实际症状逐项评估五类治疗用途，指南或药品说明书作为临床依据；年龄和性别用于适用性、安全性筛选，不制造适应证。
   提取器增加 clinicalContext，保留实际填写的合并疾病、既往病史、当前用药、用药效果、肝肾功能、妊娠/哺乳状态及手术史。空值不推定正常，历史不推定为当前治疗阶段。
2. 每个用途记录原表字段与值、临床推理及候选；每个候选记录适应证、安全评估、是否可选、是否选中、排除理由和可选的等效组。临床依据需可查证，不能把记录完整误作医疗正确性保证。
3. build_workbook.mjs 必须接受 --review，缺少或不一致时停止导出。核对每位患者顺序、五类用途覆盖、原表事实、布尔状态、候选去重、已选药与最终药物一致。可选的非等效候选不得被悄悄遗漏；同用途等效组必须择一并符合既有稳定选择器。
4. 先应用现有公司产品排除规则，再核对最终用药。六键 records 与十七列模板不变；旧手写 CLI 调用需补充 --review。
5. 不增加无依据药物、不生成患者文件、不变更已有医学剂量规则，不提交或推送 GitHub。
6. 更新技能到 1.1.16，备份并同步本机文件。

验证：失败先行的单元测试涵盖覆盖、事实错配、缺失理由、遗漏、凑药、等效选择、临床安全条件未排除等；阶段一 CLI 回归及缺少 --review 的集成测试。保留原过敏、处方映射、药品规格检查。
