# 用药方案确认时间排除服务结束日设计

## 背景

阶段 3 当前会从患者激活时间之后至激活月份月底之间生成用药方案确认时间，因此确认时间可能落在服务周期最后一天。业务要求服务周期最后一天不能出现确认时间；患者激活日期若恰好等于服务周期最后一天，应停止生成并提示修改激活日期，而不是静默排除患者。

## 规则

- 服务周期结束日期是确认时间的排他上界，确认时间必须早于该日 `00:00:00`。
- 确认时间仍须严格晚于患者激活时间，并位于每日 `06:00:00–21:59:59`。
- 确认时间仍须保持在激活时间的同一年、同一月份。
- 当患者激活日期等于服务周期结束日期时，立即报错：`<userid>的激活日期不能为服务周期最后一天，请修改激活日期`。
- 不静默过滤患者，不生成部分患者结果。
- 同一患者的所有药品行继续共用一个稳定确认时间；相同 `userid`、激活时间和服务结束日期重复生成时结果一致。

## 数据流

1. 提取器解析服务周期和患者激活时间。
2. 提取器在输出患者 JSON 前检查激活日期是否等于服务结束日期；命中则停止并报错。
3. 构建器重新执行相同边界检查，防止绕过提取器直接构建。
4. 构建器把服务结束日期传给确认时间生成器。
5. 生成器只枚举从激活时间之后到服务结束日前一日 `21:59:59` 的合法秒数，再按稳定散列选择一个时间。
6. 若没有合法时间窗口，停止并报告对应 `userid`，不跨入服务结束日或下一个月。

## 示例

服务周期为 `2026-08-01 至 2026-08-31`：

- 激活时间 `2026-08-12 11:00:00`：确认时间可落在 `2026-08-12 11:00:01` 至 `2026-08-30 21:59:59` 的合法日间时段。
- 激活时间 `2026-08-30 21:59:58`：唯一剩余合法时间可以是 `2026-08-30 21:59:59`。
- 激活日期 `2026-08-31`：停止并提示修改激活日期。

## 测试

- 单元测试确认生成时间严格早于服务结束日。
- 单元测试覆盖服务结束日前一天的最后一秒边界。
- 单元测试确认激活日期等于服务结束日期时报错。
- 提取器测试确认结束日患者触发明确错误。
- 工作簿回归测试确认所有确认时间均早于服务结束日，且同一患者多药共用一个时间。
- 重复运行测试确认结果稳定。
